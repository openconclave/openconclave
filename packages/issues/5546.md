# Issue #5546: Shift+vertex move corrupts other layers' shared vertices; cancel doesn't restore them

**Status:** Open
**Author:** BeinerChes (Ches Beiner)
**Priority:** HIGH — Data Corruption
**Date:** 2026-03-29

## Summary

When moving vertices with Shift held on a newly added layer, vertices shared with other layers also move. If the edit is canceled, the edited feature reverts but the other layer stays in the moved position — data corruption that persists on save.

## Root Cause — 5 Related Bugs

### Bug A: `_unCommonMode` not checked during moves
`MoveVertexMapFunction` sets `_unCommonMode = true` when Shift is held, but `MoveCommonVertices()` (line 690) never checks it. Shift has zero effect on vertex moves — common vertices are moved regardless.

### Bug B: `FindCommonVertices` ignores `_unCommonMode` at mouse-down
`FindCommonVertices` is called at mouse-down (line 1485) without checking `_unCommonMode`. If user clicks first then holds Shift, common vertices are already collected.

### Bug C: `UpdateCommonVerticies` is dead code
The method at line 846 (note misspelling) has zero call sites. It was meant to preview common vertex movement during drag and respect `SnapMode`/Shift, but was never wired up. This is likely related to [#5266](https://github.com/Alpine-Land-Information-Services/Atlas3_EDEV/issues/5266).

### Bug D: Cancel after drop doesn't restore other layers
`RestoreCommonVertexFeaturesGeometry` depends on `MovedVertices` which is only populated during `DropVertex`. If the drop happened but then cancel is invoked, the restore may fail if the `MovedVertices` state is inconsistent. Mid-drag Escape leaves no cleanup path.

### Bug E: New layers default to `CommonLayer=true`
Newly added layers are automatically marked as common layers (`SnappableLayer.cs:196`), meaning their vertices are always included in shared-vertex operations without user awareness.

## Suggested Fix Direction

1. Check `_unCommonMode` in `MoveCommonVertices()` — skip common vertex moves when Shift is held
2. Check `_unCommonMode` before `FindCommonVertices()` at mouse-down
3. Wire up `UpdateCommonVerticies()` or remove the dead code
4. Ensure `RestoreCommonVertexFeaturesGeometry()` works correctly in all cancel/undo paths

- `Atlas.Controls/Atlas3/MapFunctions/CommonVertexManager.cs` — `FindCommonVertices`, `CommonVertex` storage
